
# Projects Overview .NET Implementation Specification

## Objective

Implement the Projects Overview functionality in the existing C#/.NET backend.

The backend must read data from the existing PostgreSQL analytical view:

```sql
public."VW_PROJECT_OVERVIEW"
```

The analytical view is already deployed in the shared Supabase database and must not be recreated or modified.


___________________________________________________________________________________________________________________________________________________________


## 1. PROJECTS SUMMARY

### Endpoint

`GET /api/projects/summary`

### Database Query

```sql
SELECT
    COUNT(*)::INTEGER AS total_projects,
    COUNT(*) FILTER (
        WHERE has_cost_data
    )::INTEGER AS projects_with_cost_data,
    COUNT(*) FILTER (
        WHERE is_analytics_ready
    )::INTEGER AS analytics_ready_projects
FROM public."VW_PROJECT_OVERVIEW";
```
### Response
```
{
  "totalProjects": 1662,
  "projectsWithCostData": 432,
  "analyticsReadyProjects": 359
}
```

**The numbers above are examples. Actual values must be returned from the database.**

## 2. PROJECT LIST 

### Endpoint

`GET /api/projects`

### Query Parameters

| Parameter         | C# type    | Required |        Default | Validation                |
| ----------------- | ---------- | -------: | -------------: | ------------------------- |
| `search`          | `string?`  |       No |         `null` | Maximum 200 characters    |
| `min_floor_area`  | `decimal?` |       No |         `null` | Must be 0 or greater      |
| `max_floor_area`  | `decimal?` |       No |         `null` | Must be 0 or greater      |
| `levels`          | `int?`     |       No |         `null` | Must be 0 or greater      |
| `has_cost_data`   | `bool?`    |       No |         `null` | —                         |
| `analytics_ready` | `bool?`    |       No |         `null` | —                         |
| `page`            | `int`      |       No |            `1` | Minimum 1                 |
| `page_size`       | `int`      |       No |           `25` | Between 1 and 100         |
| `sort_by`         | `string`   |       No | `project_name` | Must use an allowed value |
| `sort_order`      | `string`   |       No |          `asc` | `asc` or `desc`           |


### Allowed Sort Values

- project_name
- floor_area
- total_cost
- selling_price
- total_selling_price
- margin_percent
- selling_price_per_sqm

**The value selling_price must map to the database column:** `total_selling_price`

### Validation Rules

Return HTTP 422 when:
- sort_by is not one of the allowed values;
- min_floor_area is greater than max_floor_area;
- pagination or numeric parameters are outside the permitted range.

## Filtering

Apply filters only when their values are provided.

### Project Name

```sql
project_name ILIKE '%' || @Search || '%'
```

### Minimum Floor Area
```sql
floor_area >= @MinFloorArea
```
### Maximum Floor Area
```sql
floor_area <= @MaxFloorArea
```
### Number of Levels
```sql
number_of_levels = @Levels
```
### Has Cost Data
```sql
has_cost_data = @HasCostData
```
### Analytics Ready
```sql
is_analytics_ready = @AnalyticsReady
```

**All SQL parameters must be parameterised.**

**Do not build filter values directly into the SQL string.**

___________________________________________________________________________________________________________________________________________________________

## Sorting

The final query must sort using the selected permitted column.

Use:

```sql
ORDER BY selected_column ASC|DESC
NULLS LAST,
project_id ASC
```

The project_id ASC ordering is used as a stable secondary sort.

Do not allow arbitrary column names from the HTTP request to be inserted directly into SQL.

Use a fixed mapping of allowed sort values.

___________________________________________________________________________________________________________________________________________________________


## Pagination

### Calculate the offset:

`offset = (page - 1) * pageSize`

Apply:
```sql
LIMIT @PageSize
OFFSET @Offset
```

A separate count query must return the number of matching projects before pagination:

```sql
SELECT COUNT(*)::INTEGER AS total_items
FROM public."VW_PROJECT_OVERVIEW"
WHERE <same filters>;
```

Calculate:

`totalPages = ceiling(totalItems / pageSize)`

When totalItems is zero, return:

`totalPages = 1`
